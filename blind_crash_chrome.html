DC interstitial Abort() null-deref — PoC v2

Mechanism: DigitalIdentitySafetyInterstitialControllerDesktop::Abort() dereferences dialog_widget_ with no null check. dialog_widget_ is set to nullptr synchronously the instant the native interstitial dialog closes (any cause), but the owning controller object is destroyed only by a posted task that runs slightly later. If this page's AbortController.abort() reaches the browser process inside that gap, the whole browser process crashes. See ../report.md for the full write-up.

Assisted steps:
  1. Click START (the one real click navigator.credentials.get() needs).
  2. Wait for the native “share your identity with this site?” dialog.
  3. Click its own Go back button (or press Esc) — a real, OS-level close.
  4. The page fires controller.abort() the instant focus/visibility returns. If it lands in the gap, Chrome crashes immediately.
Blind sweep steps:
  1. Click START. No further interaction — the script alone fires the navigation+abort race at the current sweep config.
  2. Watch for a crash (whole browser dies / relaunches). If nothing crashes, the log will show request settled: ... and the config index auto-advances.
  3. Click START again for the next config in the sweep (a fresh real click is required every time — the API consumes transient activation per call, this cannot be looped without a click).
  4. If Chrome crashes mid-trial, the last log line before the crash (persisted to localStorage, survives the crash/relaunch) tells you exactly which config did it.
